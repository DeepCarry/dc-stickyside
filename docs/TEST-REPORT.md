### 边缘悬浮窗口停用手型光标（2026-11-10 追加，v0.9.15）

用户复测 v0.9.14 后反馈闪烁仍在，拍板：「直接把光标移到屏幕边缘悬浮的便签窗口上时，
就显示光标原本的形状，不再显示手型」。三层修复（迟滞状态机 / runloop 观察者 / 事件监视器）
把测试打到全绿，但 floating 面板点击时同时触发 makeKey + frame 动画 + SwiftUI 视图树重建，
WindowServer 的光标所有权在这几百毫秒里被系统反复收回——竞争发生在我们的可观测面之外，
继续加补丁只是在跟系统拔河。

落地：`EdgeDeck` 摘掉全部 4 处 `.handCursor`（签列整列、抽出态空白、两颗圆钮），
`pull`/`collapse` 里的 `hold(0.6)`/`recheckNextTick()` 一并删除；手型机制保留给
主窗口 / Sheet / 便签槽这类不做 frame 动画的普通窗口。

测试调整：`--clickfliptest` 语义翻转为**守住新行为**（边缘窗口零垫片、指着纸签不进手型、
真实点击 + 抽出动画 40 帧手型 0 帧次、handSwitches/arrowSwitches 全程 +0，共 8 项）；
`--edgeclicktest` / `--clickprobe` / `--deckhovertest` 三个边缘手型测试随之删除。
`--handtest`（纯状态机，主窗口仍在用）与 `--hovertest`（主窗口真实光标）保留。

### 点击边缘便签时箭头/手型互闪：第二层修复（2026-11-10 追加，v0.9.14）

用户复测后反馈 v0.9.11 的状态机**没有治好**。复查发现旧 `--edgeclicktest` 只断言
`HandCursorRegistry.isHand`（我们进程里的状态），注释里还写着「`NSCursor.set()` 在后台
可能不生效，所以不断言真实光标」——测试全绿，但屏幕上那个由 AppKit cursor rect 管的
光标根本不在断言范围里；而且测试直接调 `pull()`、把鼠标钉死不动，没走真实点击事件。

| 层次 | 现象 | 处理 |
|---|---|---|
| 状态机 | 点击时视图树重建，垫片短暂消失 | v0.9.11 的迟滞已经解决，实测 40 帧 0 翻转 |
| 几何判定 | 点击手抖 1~2pt 让 `moved` 为真，旧 sticky 条件 `!moved` 失效 | sticky 改成**只看位置**（指针仍在命中矩形内就算命中）；位移门槛 2→6pt |
| **屏幕光标** | AppKit 在 mouseMoved / cursorUpdate / 窗口变 key 时把光标洗回箭头，我们 25Hz 轮询下一帧才补，中间 0~40ms 就是一次可见的闪 | 主 runloop `.beforeWaiting` 观察者在**每个事件结束时**同步补一次；事件监视器再无条件兜一次 |

另外把点击宽限期从「只有 `pull()` 有」改成**任何真实鼠标按下/抬起都给**
（0.55s / 0.35s）：点关闭收起、点圆钮、点面板空白这些路径以前完全没有保护。

`--clickfliptest`（10 项）用手动 `NSApp.postEvent` + `sendEvent` 派发真实事件
（CLI 测试二进制没跑 `NSApp.run()`，CGEvent 合成事件不会自己派发），每个事件前
强行 `NSCursor.arrow.set()` 模拟 AppKit 洗光标，只给 12ms（不够 25Hz 轮询补一帧）：
只有 async 事件重申时 40 帧里残留 9~10 帧箭头；加 `.beforeWaiting`/`.exit` runloop 观察者后
连跑 10 次都是 **0 帧残留、0 次翻转、0 次切回箭头**。
两条点击路径（换签 `pull` / 收起 `collapse`）都覆盖，并验证移开后仍能回箭头。

### 菜单栏图标改成实心（2026-11-10 追加，v0.9.13）

用户对比了菜单栏里其它图标后指出：别人是**实心底、细节镂空**，我们正好反了——透明底、白线条，
在那排里像一层薄线框。要求重做。

先只出设计稿（`tools/mbicon-preview.swift` → `shots/menubar/design-fill-sheet.png`），
三个候选：甲 三张扇开同 App 图标 / 乙 单张摆正 / 丙 单张 + 后面露一张。用户选了**甲**。

落地时量出四件事：

| 发现 | 证据 |
|---|---|
| 照搬 505 的后纸在 18pt 上只剩 1px 发丝，被缝一切就成噪点 | `--iconmap` 点阵 + 8x 放大图 |
| 后纸放大到 600、上提 150，两侧才有 ~2pt 实心纸边 | 同上，`bbox` 从 12pt 宽回到 16pt |
| −3.5° 前纸倾斜是"不对称"的来源：右侧露边落在上半段，左侧落在整段 | 逐列统计 ink 分布 |
| 1x 的缝加粗 1.7× 会把后纸吃光，纸形只剩前纸 | 6 组 `gapHint × contentHint` 对照 |

断言从"线稿"改成"实心 + 挖空"语义（`--menubaricon` 17 → 18 项）：

- 纸面空白处 `holes == 0`（实心），内容区 `holes ≥ 20`、勾选框内部 `holes ≥ 3`（镂空）；
- 左右两侧各有 `≥20px` 墨迹（后纸露出），并且各有一条 `≥4px` 的透明缝把它们与前纸分开；
- 顶部 `≥10px` 墨迹高过前纸顶边（说明后面还叠着纸）；
- 覆盖率 40%~54%（1x）/ 42%~56%（2x），四周留白 ≥ 0.75pt。

### 手型光标点击闪烁（2026-11-10 追加，v0.9.11）

用户报：点屏幕边缘的纸签时，光标在箭头和手型之间来回闪。

根因是判定太"急"：25Hz 轮询里「这一帧没命中就立刻变箭头」，而点一下纸签会同时触发
`makeKey()` + 窗口 frame 0.24s 动画（54pt → 392pt）+ SwiftUI 换整棵视图树（垫片销毁重建），
命中在几十毫秒里反复真假。另外两条自己也参与制造闪烁：`isCovered()` 用了 `$0.isVisible`
（动画期间为 false，我们自己的面板被判成"别人压在上面"→ 直接箭头）、`unregister()` 里立刻
`releaseHand()`（垫片重建的空窗期被当成"离开"）。

修法：`HandCursorLogic` 纯状态机 —— 进入立刻；离开要求「自上次命中以来鼠标动过 > 2pt」
且连续 4 帧（160ms）未命中；按键期间不切；`pull()` 时 `hold(0.6)` 钉住整段动画。
命中判定改为遍历本 App 所有可见窗口的垫片（不再只认 `windowNumber`），并加 sticky 记忆
（上次命中的屏幕矩形外扩 3pt，手没动就继续算命中）。

断言：`--handtest` 15 条（含"命中/未命中交替 20 帧 0 次切回箭头"、"手不动 20 帧不切"、
"动过之后停住仍能离开"），`--edgeclicktest` 6 条（真实窗口 pull 后采 32 帧：32/32 手型、
0 翻转、0 次走回箭头分支；修复前实测 29/32、3 次箭头）。`--deckhovertest` 也加了同样的
点击采样 4 条。

### 手型光标（2026-11-10 追加）

用户反馈「鼠标移到可点击按钮上不变手型」。实测 SwiftUI 按钮在 AppKit 层是私有
`KeyViewProxy`，不是 `NSButton`，无法按类型全局处理。

**v0.9.5 的 cursor rect 方案在真机不生效**：`--hovertest` 只断言了「垫片注册了 1 个 cursor rect」，
测试全绿，但鼠标移上去仍是箭头。用真窗口探针复现（`CGWarpMouseCursorPosition` + `NSApp.run()`
事件循环）后确认：同一垫片挂在普通 `Color` 上能变手型，挂在 `Button` 上（`background` 与
`overlay` 都试过）一律失效——`cursorUpdate` 只会派发给光标下那个 SwiftUI 私有视图。

v0.9.6 改为 `HandCursorRegistry`：每 40ms 读一次 `NSEvent.mouseLocation`，逐个判断是否落在
某个 `HandCursorView` 的可见矩形内，不依赖任何事件派发；进入/离开的瞬间切换光标，区域内
只做幂等 `set`；离开时按落点还原 `.iBeam`（可编辑文本）或 `.arrow`。另修一个隐蔽坑：
**`NSView.visibleRect` 在 SwiftUI 托管视图里返回整个窗口大小**（每个垫片都报 1100×788），
改为逐级与祖先 `bounds` 求交集。

`--hovertest` 现在真的移动系统光标，12 项断言：进程为前台 / 窗口拿到 key / 可点击区域 36 个 /
垫片不吞点击 / 5 个真实按钮与卡片区域变手型 / 输入框保持非手型 / 窗口空白处恢复箭头。
覆盖 58 处可点击视图：顶栏按钮、墙标签、输入区纸色与标签、筛选 chips 与四个菜单、整张便签卡片、
卡内勾选框与「⋯」菜单、捕获面板、设置页（Picker / Toggle / 快捷键录制）、详情页、回收站、边缘条与刘海入口。
输入框一律不加，保持 I 形光标。

### 输入法吞字回归（2026-11-10 补测）

用户报「中文输入法打一个字母，字母自动被删」。根因链条：

1. 占位探针每 120ms 发布 `@Published` → SwiftUI 重算含 `TextEditor` 的视图树 →
   空 binding 被写回 `NSTextView`，未上屏拼音被抹掉；
2. 只把探针挪出 SwiftUI 后，`--imetest` 仍测出**无关的** `@Published`（Toast / store）同样会吞字；
   `.equatable()` 隔离实测无效。

修复：`EditorPlaceholderView` 原生绘制占位 + `PlainTextEditor` 自托管 `NSTextView`，
只在 binding 值真的改变且不在组合态时写回。**四处**输入框全部替换（主输入区、捕获面板、
便签详情、边缘条抽出面板）——最后一处每次 `onEdit` 都写回 store，是最容易吞字的地方，
`--edgetest` 里也补了 2 条组合输入断言。

补测覆盖：首个字母、连续拼音、无关发布、选词上屏、清空、占位显隐、草稿不混入拼音、
binding 双向同步、英文直输，以及真实主窗口里
「键入 → ⌘↩ → 便签落盘 → 清空 → 占位复现」全链路。

## 三、本轮修复的问题（用户反馈）

1. **捕获面板 ⌘↩ 无反应**

3. **「待办」标签没有实际作用**

   修复：选中「待办」时保存自动把每行转成 `- [ ] 内容`（已是清单行不重复加），并在输入区提示；同时在主输入区补上标签选择（之前完全没有入口）。

### 边缘条手型（2026-11-10 追加，v0.9.7）

用户第三次反馈：「悬浮在屏幕边缘的这个窗口，这里没有变成手型」。

先加 `--deckhovertest`：真的建出边缘条面板、逐张签 warp 光标、读 `NSCursor.current`。
第一次跑就复现了——**四张签里只有最上面那张有手型**，下面三张全是箭头（两颗圆钮一直是好的）。
原因是每张签各挂一个手型垫片，而签带 `.offset(y: idx*68)` + `rotationEffect`：
SwiftUI 给这种子视图报的窗口矩形不可信，实测 4 张里 2 张算成 `(inf, inf, 0, 0)`、
1 张只剩半个高度。修法两条：

1. `windowRect(of:)` 只跟**真正裁剪**的祖先（`masksToBounds`）和窗口内容区求交，
   不再逐层跟布局容器求交（偏移出去的子视图会被容器原地 bounds 误杀）；
2. 纸签整列挂**一个**垫片（列的 `frame` 是规规矩矩的，签按 68pt 步进重叠，列矩形 = 各签并集）。

同时去掉 `HandCursorRegistry.tick()` 里的 `guard NSApp.isActive`：边缘条是 `nonactivatingPanel`，
悬停不会激活 App，这道门槛让「在别的 App 里干活、顺手去够边缘条」永远拿不到手型。

`--deckhovertest` 13 项断言：4 张签逐张手型 / 2 颗圆钮手型 / 面板外箭头 / 抽出态关闭按钮手型 /
抽出态编辑区非手型 / 面板 key / 垫片数量。**并用 `screencapture -C` 连光标一起截图取证**
（`shots/edge-cursor-tab2.png`、`edge-cursor-tab4.png`，肉眼可见第 2、4 张签上是手型），
因为 `NSCursor.current` 只反映 App 自己的状态、不能单独作为「屏幕上真的变了」的证据。

#### 一个必须写清楚的系统限制

App 在**后台**时 macOS 不允许任何 App 改光标。真机取证：同一个位置，前台时截图是手型，
`open -a Chrome` 把前台让出去之后立刻变回箭头。三种公开做法全部无效（定时 `NSCursor.set()`、
`resetCursorRects`、`NSTrackingArea(.cursorUpdate)`），私有的 `SetsCursorInBackground` 在
macOS 15 上也已失效。所以验收必须在**便签墙是前台 App** 时做；后台悬停显示箭头是全 macOS 的
统一行为，不是本项目可修的 bug。
